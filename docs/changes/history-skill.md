# history-skill: Date provenance and evidence gaps

Status: proposed; available after this skill’s pull request merges.

Distinguish commit, merge, release, and deployment dates and preserve contradictory or missing historical evidence.

## Research and adaptation

- [Matt Pocock research](https://github.com/mattpocock/skills/blob/main/skills/engineering/research/SKILL.md): trace claims to primary sources.
- [Matt Pocock retro](https://github.com/mattpocock/skills/blob/main/skills/engineering/retro/SKILL.md): inspect primary records before drawing lessons.

Use source-backed chronology without importing retrospective environment changes or automatic background delegation. Research inspected on 2026-10-30; upstream links may evolve. The changes use original wording.

## Review examples

**Representative request:** Summarize when a feature became available: authored October 1, merged October 3, released October 5, deployment unknown.

**Expected behavior:** Keep the three dates distinct and do not claim a deployment date. Record source cutoff and unresolved availability evidence.

**Boundary request:** What does this function do?

**Expected boundary:** Explain the function; do not create a project history.

These are manual instruction walkthroughs, not independent model evaluations or rendered-output tests. Metadata checks cannot establish that a generated artifact works.
